# Case 08

Request: “Create a feature extending provider pricing to native billing units.
Develop with quick feedback and complete the normal verified delivery. Give me
its discovery and test-execution plan before implementation.”

Raw task facts:

- One request schema is consumed by an existing HTTP price writer, MCP preview/
  apply, database storage and an admin editor. There are three provider families.
- The current currency and amount fields are flat USD rates. Native rates can use
  credits, request minimums and schedule/context tiers. A persisted cost column is
  a PostgreSQL integer; caller token counts can be absent on transport failure.
- Existing domain tests cover flat-rate calculations. A draft native parser unit
  file passes; no native SDK-to-database settlement case has been exercised yet.
- Candidate fast selections take a few seconds; a real SDK/database integration
  case needs disposable PostgreSQL. The full critical backend stage takes about
  12 minutes. Its migration setup has not been measured after the proposed schema
  extension; a previous cold run needed 14 seconds with a default 10-second hook.
- The app has mapped browser journeys and current legacy accounting tests. Existing
  critical rules require the full gate for shared accounting/provider changes.
- No implementation/source review has run. The requested feature is authorized;
  paid provider calls and production mutation are not authorized.

Return the bounded discovery outputs, first proofs, development selections,
source-review/final-gate sequence, start conditions for broad execution and the
response to a late fixture or setup failure. State when completion can be approved.
This is a read-only decision probe, not a request to implement or run checks.
