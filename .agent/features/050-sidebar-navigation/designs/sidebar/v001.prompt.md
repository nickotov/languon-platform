Task: Redesign Languon's Navigation Sidebar

1. Your role

Act as a Senior Product Designer, UX Architect, and Staff Frontend Engineer specializing in modern productivity applications, AI-powered learning platforms, and scalable navigation systems.

Your task is to rethink and redesign the main navigation sidebar of Languon, taking inspiration from mature products such as Linear, Notion, Raycast, and other high-quality desktop-first productivity applications.

Use Magic Patterns to explore and refine the visual design and Codex to inspect the existing application and implement the final solution.

Do not simply restyle the existing sidebar. Reconsider its information architecture, layout, interaction model, visual hierarchy, responsive behavior, and future extensibility.

The outcome should be a production-quality navigation system that looks modern, coherent, and premium without becoming visually noisy or unnecessarily complicated.

4. Current navigation problems

The existing sidebar has several issues:

Dictionaries contain a permanently visible nested list, whereas Texts and Knowledge have no comparable treatment.

The visual hierarchy is weak and relies heavily on indentation.

Creating, opening, browsing, and expanding content are represented inconsistently.

The expanded sidebar will become difficult to use when users have many resources.

The collapsed sidebar has ambiguous icons and a standalone plus button without enough context.

There is no universal mechanism for quickly accessing recently used resources.

The account popup feels visually disconnected from the sidebar.

Future features would make the current flat navigation increasingly cluttered.

The design needs better coordination with content-heavy pages, especially the editor + AI chat layout.

Solve these structural UX problems, not just the visual appearance.

5. Recommended architectural direction

Use a hybrid contextual navigation system.

It should combine:

Persistent navigation to primary application areas.

Expandable quick-access lists for commonly used resources.

Contextual flyouts when the sidebar is collapsed.

Universal resource search and quick actions.

Responsive navigation behavior for desktop, tablet, and mobile.

Explore this direction and refine it based on your assessment of the real application.

Do not interpret these suggestions as a requirement to reproduce a fixed layout. You should improve the proposal wherever a better interaction is justified.

6. Desktop expanded sidebar

Design a compact, visually balanced sidebar approximately 250–280px wide, adjustable if the existing design system suggests a better value.

Header

Include:

Languon identity.

Collapse control.

Possibly a compact workspace switcher if this becomes necessary.

Avoid oversized branding.

Quick search

Provide a visible universal search entry point.

Expected capabilities:

Open search using Cmd+K / Ctrl+K.

Search across supported content types.

Navigate directly to results.

Show recent results and useful actions if available.

If cross-resource search is not implemented, design the interaction now but do not fabricate backend functionality. Preserve working existing behavior and document any follow-up implementation required.

Global create action

Consider a compact universal "Create" action.

It should eventually support:

New dictionary

New text

New knowledge document

New lesson

New course

Only show actions supported by the actual app.

Do not duplicate prominent creation controls throughout the sidebar unnecessarily.

Main navigation

Show primary destinations with:

Consistent icons.

Consistent typography and alignment.

Clear hover, focus, and selected states.

Appropriate semantic grouping.

Sufficient spacing without wasting vertical space.

Expandable resource sections

For Dictionaries, Texts, Knowledge, and future resources:

Selecting a section title should navigate to its overview.

A separate disclosure control should expand or collapse its resource list.

A contextual create control may appear on hover/focus in desktop mode if discoverability remains good.

Expanded content should show a few recent or pinned resources.

Provide a clear "View all" destination.

Support long titles using truncation and full-title tooltips.

Display helpful metadata only where it provides real value.

Support empty, loading, error, and populated states.

Avoid dumping entire collections into the global sidebar.

Prefer a small, manageable set of resources (approximately 3–5) unless the user explicitly expands a longer list.

Use section-specific behavior where justified:

Dictionaries: recent or pinned dictionaries; optionally language-pair metadata.

Texts: recent texts and relevant folders.

Knowledge: recent documents and optionally relevant folders.

Courses: active courses and progress-related shortcuts in the future.

Lessons: current or recently edited lessons when implemented.

Don't build deeply nested trees in the permanent sidebar.

Footer

Include a compact account control anchored at the bottom.

Redesign the account popup to contain:

Profile and account entry.

Interface language.

System / Light / Dark theme selection.

Settings access.

Logout, visually separated from normal preferences.

The popup should feel like part of the same visual system.

It should be positioned reliably, remain inside the viewport, and never be clipped by the sidebar or editor.

7. Desktop collapsed sidebar

The collapsed sidebar should be a first-class navigation mode, not simply the expanded sidebar with labels hidden.

Target width: approximately 60–72px.

Requirements:

Clearly identifiable primary destinations.

Consistent icon sizing and positioning.

Accessible tooltips.

Visible active state.

No unexplained standalone action icons.

Quick access to frequently used content.

Keyboard accessibility.

Contextual flyouts

Explore contextual flyouts that open from collapsed navigation icons.

For example, hovering or focusing the Dictionaries icon could open a panel containing:

Dictionaries

View all dictionaries

Create dictionary

Recent / pinned dictionaries

Optional resource search

Equivalent flyouts should work for Texts and Knowledge.

Future Lessons and Courses should be able to use the same navigation primitive.

Flyouts should:

Open with a short, intentional delay for hover.

Remain open when the pointer moves into the panel.

Avoid flickering or disappearing during pointer movement.

Support click and keyboard activation.

Close correctly with Escape and outside interaction.

Remain inside the viewport.

Avoid obscuring content unnecessarily.

Avoid remounting or resetting the current editor.

Important: Hover must be an enhancement, not the only method of reaching nested content.

Do not create a permanently visible secondary sidebar by default. Explore whether temporary contextual panels are a better use of horizontal space.

8. Mobile and tablet navigation

Do not reproduce the desktop icon rail on narrow mobile screens.

Design an intentional responsive experience.

Mobile

Prefer:

Compact application header with navigation trigger.

A full-height, dismissible navigation drawer.

Primary navigation groups clearly separated.

Expandable content lists inside the drawer.

Search and create actions accessible without complex gestures.

Account and settings at the bottom.

Accessible touch targets of approximately 44px or larger.

Avoid hover-only interactions.

Consider whether a small bottom tab bar would genuinely help frequent workflows. Do not introduce one automatically if it duplicates the drawer or creates navigation complexity.

Editor on mobile

The text or knowledge editor should remain the primary visual focus.

Navigation should not permanently consume editor width.

Ensure contextual AI assistance can still be accessed without conflicting with global navigation.

Tablet

Consider using a collapsible rail or drawer depending on available width and the complexity of the current page.

Base behavior on actual content space, not merely device names.

9. Visual design direction

The desired style is:

Premium, calm, minimal, professional, contemporary, and learning-focused.

A balance between:

Linear's density and precision.

Notion's flexible navigation.

Raycast's efficient interactions.

A friendly but serious educational product.

Do not copy their exact branding or components.

Colors

Keep compatibility with dark and light themes.

The existing interface primarily uses dark neutral surfaces with purple/indigo accents.

You may refine this direction.

Prefer:

Sophisticated dark neutral surfaces.

Subtle separation between the sidebar and application content.

One clear accent color.

Muted secondary text.

Restrained active item backgrounds.

Consistent icon colors.

Strong enough contrast for accessibility.

Avoid:

Excessive gradients.

Neon outlines.

Heavy borders around every block.

Too many surface shades.

Arbitrary accent colors.

Decorative glassmorphism without functional value.

Typography

Establish a clear hierarchy for:

Brand.

Navigation labels.

Section headings.

Resource names.

Metadata.

Menu options.

Use consistent weights, line heights, and font sizes.

Don't make labels unnecessarily small just to fit more content.

Spacing

Use a consistent spacing system.

Target navigation item heights approximately 40–44px on desktop.

Maintain enough density for productivity without creating cramped layouts.

Icons

Use a coherent icon family and consistent stroke weight.

Each main destination must be visually distinguishable, especially when the sidebar is collapsed.

Avoid using nearly identical book icons for unrelated destinations.

Motion

Use restrained animation for:

Sidebar expansion and collapse.

Flyouts.

Section disclosures.

Menu transitions.

Active item transitions.

Motion must not delay navigation or cause layout instability.

Respect reduced-motion preferences.

Localization

The UI currently uses Russian and supports configurable interface languages.

Ensure:

Russian and English labels fit correctly.

Text truncation is handled gracefully.

Language-pair labels remain understandable.

Wider translated strings do not break layout.

Closing menus with Escape.

Active states

The active parent section must remain recognizable when a nested resource is open.

Use different visual treatments for:

Hovered item.

Keyboard-focused item.

Selected destination.

Expanded section.

Keyboard access

Use semantic navigation links and buttons.

Ensure active links expose appropriate accessibility state.

Performance and state

Avoid loading every user's resource into navigation on initial page load.

Use existing query/caching mechanisms.

Load contextual resource data efficiently.

Preserve editor and AI chat state during sidebar expansion/collapse.

Avoid introducing extra navigation remounts.

Persist sidebar preferences appropriately.

Prevent hydration mismatches when restoring UI preferences.

11. Future extensibility

Design the system so new navigation destinations can be added declaratively.

A navigation section should support configurable:

Label / localization key.

Icon.

Destination.

Group.

Visibility conditions.

Optional create action.

Optional resource preview.

Optional nested resources.

Active route matching.

Avoid hard-coding special behaviors for each individual section.

However, do not over-engineer a generic navigation framework. Prefer a small, clear, type-safe architecture based on actual product requirements.

The navigation should scale naturally when Lessons, Courses, and Tutor workflows are introduced.

12. Design exploration workflow

Before implementing the final design, use Magic Patterns to explore at least two distinctly different navigation concepts.

Concept A — Contextual expandable sidebar

An expanded sidebar with grouped primary navigation, compact recent-item lists, and contextual flyouts in collapsed mode.

Prioritize quick access and minimal horizontal footprint.

Concept B — Navigation rail with adaptive resource browser

A compact primary rail with a contextual resource-navigation panel that appears when useful.

Explore whether separating primary destinations from resource browsing provides better usability, especially for complex future workflows.

Consider its disadvantages:

More horizontal space.

More navigation layers.

Potential complexity on editor + AI chat screens.

Compare both concepts in terms of:

Visual quality.

Discoverability.

Speed of common actions.

Complexity.

Scalability.

Mobile adaptation.

Accessibility.

Implementation effort.

Select the strongest concept based on the application's actual workflows rather than personal aesthetic preference.

You may combine ideas from both if that produces a better result.

16. Success criteria

The redesign should make Languon feel like a mature, premium AI-first learning workspace.

A successful result should satisfy these principles:

Primary features are discoverable immediately.

Creating content requires minimal interaction.

Recently used resources are accessible quickly.

Navigation remains manageable with hundreds of resources.

The collapsed sidebar is genuinely useful.

The editor and AI assistant retain sufficient working space.

Mobile navigation feels intentional, not like compressed desktop UI.

New product features can be introduced without redesigning the entire sidebar.

The design is visually consistent and accessible.

Existing application functionality continues to work.

Most importantly: prioritize excellent information architecture, intuitive interaction, and visual consistency over decorative styling.

Do not simply add more icons, gradients, or visual effects.

Build a navigation system that users can rely on every day.
