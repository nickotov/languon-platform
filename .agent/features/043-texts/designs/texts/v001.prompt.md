## Portable Magic Patterns prompt

Design a complete responsive web feature called **Texts** for Languon, a language
learning app with dictionaries and learning cards. Learners organize passages in
folders, translate complete passages with AI, compare aligned sentences, and
collect words or short phrases into their dictionaries using the passage context.
Produce a clickable prototype with realistic content and all specified states.

### Existing app and visual direction

Use the existing Languon project/design reference as visual authority. Extend its
shared shell, navigation, language controls, dialogs, forms, buttons, menus, badges,
toasts and dictionary presentation. The current app has a desktop sidebar, an
expandable Dictionaries navigation group, a responsive mobile navigation drawer,
and a global profile/preferences entry. Add **Texts** as a clear peer beside
Dictionaries; keep the current navigation hierarchy and preferences placement.

The app uses warm neutral surfaces, dark blue-gray text, restrained blue actions,
subtle borders/shadows, rounded controls and cards, and compact Lucide-style icons.
Use the same typography and spacing as the supplied existing project. Reading is
the main focus: comfortable line length, clear language labels, generous text
leading, calm highlights, strong keyboard focus. Use English interface copy and
leave room for translated labels. Show desktop around 1440 px and phone around 390 px,
including narrow 320 px behavior without horizontal page scrolling.

### 1. Texts library and folders

The Texts landing screen lists the learner’s folders and has a prominent **New
folder** action. A folder has a required name and optional short description.
Support creation, opening, renaming/description editing, archive, and restore.
Folders are flat; no nested-folder interaction. Show loading, empty, populated,
failed-load/retry, and archived-list states. An empty library explains the purpose
in one short sentence and offers New folder. Use realistic folder names such as
“Daily reading” and “Travel stories.”

Inside a folder, show its name, optional description, a back/breadcrumb path, and
**Add text**. List saved texts with useful title, source→translation languages and
Draft/Translated/Edited after translation state. Allow opening existing texts and
archiving/restoring them. Present folder details and sharing in a restrained menu
or header action. Support title-only edits. Do not add nested folders, moving,
permanent deletion, file upload, PDF/image extraction, or rich-text formatting.

### 2. Fullscreen text workspace

Add text opens a fullscreen dialog/workspace. Keep a clear close/back action,
folder context, optional title, explicit **Source language** and **Translation
language** selectors, and primary actions visible. Source and target must differ.
If title is omitted, the first nonempty source line becomes the saved title.

Before translating or saving, the learner explicitly chooses/confirms both
languages. Provide a separate **Detect language** action beside source language.
Detection is optional: show detecting, a suggested language with **Use this
language**, low-confidence/unknown, and failure/retry states. Never silently
replace a selected language or automatically translate because detection finished.
The learner can always choose manually.

On desktop, show source input in one column and translation in the adjacent
column. Before translation the second column explains that the result appears
after **Translate via AI**. Preserve paragraph breaks, punctuation and source
spacing. Display a discreet source character count with a 20,000-character maximum;
empty/over-limit input has inline feedback. Valid input can still exceed a
particular AI model’s capacity; provide a friendly shorter-text/other-model
recovery state without partial or silently truncated translations.

Translate via AI processes the whole passage with context. Show queued and
translating states, cancellation where available, failure with retry, and a
completed preview. Preserve input on every failure. Provide **Save draft** before
translation and an explicit **Save** for a completed translation. Generating a
translation does not automatically save it. Show unsaved/saving/saved states and
an unsaved-changes confirmation on close. A generated preview may expire after
24 hours; show a useful regenerate action if it can no longer be saved or used.

Opening a saved translated text starts in read mode. Both columns are read-only.
The learner enters editing only with **Edit text**. In edit mode, both source and
translation can be edited as corresponding sentence blocks. Keep their pairing;
there is no arbitrary split, merge, reorder or deletion of sentence pairs. Offer
**Save changes** and **Cancel editing**. Changed pairs and the overall document
show **Edited after translation**; manually typing the original wording back does
not clear that provenance. Do not silently claim edits were checked by AI.

Provide explicit **Retranslate via AI**, explaining that it can replace manual
translation edits. Keep the last saved version safe while generation runs or
fails. Present the new result as an unsaved proposal and replace the saved result
only after Save. Successful fresh translation has fresh alignment/provenance.
If another device changed the saved text, explain the conflict, keep the local
work visible and offer reload/review; never silently overwrite newer content.

### 3. Sentence matching is an explicit reading mode

Provide a clearly labelled toggle/button, **Match sentences**, initially off.
When enabled, hover or keyboard-focus a source sentence to highlight that sentence
and its corresponding translation in the neighboring column. The reverse works
from translation to source. The translation of one source sentence can contain
more than one target sentence; highlight that whole corresponding block. Keep
paragraph layout readable and make corresponding content easy to locate while
scrolling. Do not require matching mode for ordinary text selection.

On phones, avoid two squeezed columns. Use clearly labelled Source/Translation
tabs with visible language names. When matching is enabled, tapping a sentence
shows its counterpart in an accessible sheet/panel with both language labels;
provide a clear way back to reading. Provide keyboard and touch alternatives to
hover. Highlights must not rely on color alone and must not obscure native text
selection. Match mode has a clear active state and can be turned off.

### 4. Select a word or phrase and add it to a dictionary

In read mode, allow native selection in either source or translated text. Show a
small anchored popover above/beside a valid selected word or short phrase with
**Add to dictionary**. Support repeated occurrences correctly: retain the selected
occurrence, not just its spelling. The selection must remain within one actual
sentence and at most 200 characters. For cross-sentence or too-long selection,
explain how to narrow it. Keep touch selection handles usable; on narrow screens
use a viewport-safe popover or bottom sheet without losing the selection.

Clicking Add to dictionary opens the dictionary choices inside that popover/sheet.
Show the selected phrase and a short containing-sentence preview for context.
Existing dictionaries are selectable; show an empty-list state and **Create new
dictionary**. The new-dictionary path asks for a required dictionary name, then
has a clear **Create and add** action. Include back/cancel, loading, validation,
search/filter if needed for a long dictionary list, and disabled/busy states.

Show the language direction used for the new card. Selecting from translation
reverses the original passage direction. For example, English→Spanish passage:
selecting “banco” on the Spanish side makes a Spanish→English card. Context includes
the containing sentence and neighboring sentences, so an ambiguous word receives
the sense used here. A subtle “Using sentence context” cue is enough; keep technical
details out of the learner flow.

Explicit Add/Create and add authorizes AI to generate and save a complete learning
card: selected word/phrase, contextual translation, definition, example and example
translation. Do not invent another mandatory review/approval screen. These cards
include all learning fields even if the selected dictionary normally hides some;
communicate any relevant card-level behavior without changing dictionary defaults.
Adding to a new dictionary creates the dictionary and card together only when the
operation succeeds. Show processing and prevent accidental repeated submission.
If the word is already present, ask whether to add another card intentionally;
never silently duplicate it.

On success, show a toast such as **Added “bank” to Daily reading** with an explicit
**Open dictionary** link to the actual destination. On failure, show an actionable
reason and retry/recovery. Cover unavailable AI/model, insufficient credits,
expired preview, unavailable/revoked source, changed dictionary, and network
uncertainty. A lost response must not imply the user should submit a duplicate:
show checking/pending until the existing operation’s result is known. The learner
can keep reading while collection finishes. Use accessible live announcements.

Use a realistic sample to demonstrate contextual meaning: English source “We
walked along the river. She sat on the bank and opened her book. The water was
quiet.” with Spanish translation “Caminamos junto al río. Se sentó en la orilla y
abrió su libro. El agua estaba tranquila.” Selecting “bank” should lead to the
river-edge sense, “orilla,” with matching definition and example. Include another
longer, multi-paragraph passage for scrolling and phone layouts.

### 5. Sharing and independent copies

Support sharing a saved translated text or an entire folder through an unlisted
link. Make the visibility clear: **Anyone with the link can read**. Show create/copy
link, copied feedback and revoke confirmation/success. Link revocation must have a
clear effect. Sharing is available only for saved translated content. A shared
folder is live: newly saved translated texts and later edits appear; drafts and
archived items do not. Explain this briefly at sharing time.

A shared text/folder has a clean read-only public view and the same sentence
matching/reading affordances. Anonymous visitors can read; adding vocabulary or
making an independent copy requires sign-in. Offer a clear sign-in continuation.
Signed-in visitors can collect vocabulary, copy a text into their own folder,
copy an individual text from a shared folder, or copy the whole shared folder.
Label copies as independent: later source edits or revocation do not change saved
copies or collected cards. Show destination choice, working, success, duplicate
click protection and failure. A whole-folder copy supports up to 500 translated
texts; if exceeded, suggest copying individual texts instead.

A revoked link, archived source, missing source or unavailable source account
shows the same calm unavailable state with a route back to the app. Do not reveal
private owner details. Archiving a shared text/folder disables its links;
restoring leaves it private until shared again. Present archive consequences
before confirmation and make Restore discoverable in the owner’s archived list.

### 6. Responsive, accessible and complete states

Use the full viewport workspace on desktop and phone. Keep actions reachable above
the software keyboard and safe areas. Phone popovers/sheets must fit 320–390 px
screens, avoid clipped menus, and preserve reading position across tabs. Make
long titles, long dictionary names, long sentences and translations wrap safely.
Use sensible loading skeletons/progress, inline form errors, disabled explanations,
toasts with links, and empty-state calls to action. Avoid fake percentage progress.

All controls need visible focus and names, labelled fields, keyboard navigation,
adequate contrast and touch targets. Dialogs/sheets trap focus, support Escape
when safe, and restore focus on close. Unsaved or in-flight destructive actions
need deliberate handling. Sentence matching has equivalent keyboard/touch access.
Present AI failures in plain language; do not surface internal identifiers,
provider credentials, raw server payloads, schema details or job tables.

Deliver connected screens for: folder library; new/edit folder; folder contents;
new text; detection; generation; completed unsaved preview; saved read mode;
matched sentences; explicit pair editing; retranslation; vocabulary popover,
dictionary picker and new-dictionary subflow; success/error toast; share dialog;
public text/folder; copy flows; archive/restore; and representative recovery states.
Show the main reading/selection journey on desktop and phone. This prototype is a
design handoff: real persistence, authentication and AI are supplied by the app.
