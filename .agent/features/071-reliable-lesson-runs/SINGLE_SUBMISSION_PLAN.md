# Complete a mixed lesson from one submission

Proposed November 19. This is a design and verification plan for feature 071. It requires a successor to ADR-0061 before the worker automatically starts a new stage following a rejected generation attempt.

## Incident evidence

The saved revision requests four parts: French reading, three reading exercises, COD/COI grammar, and five grammar exercises. The reading and two comprehension exercises are checkpointed. R04, the remaining comprehension exercise, elicited seven rejected candidates in four actions across the retry sequence. The latest saved diagnostic is a schema validation failure on acceptedAnswers. The earlier receipts establish the count of rejected candidates; they do not retain seven individual validation paths or the original candidate text.

R04 asks learners to explain the passage in their own words. Its provider schema inherits an optional answer list from the generic free-text block. Its canonical validator rejects a nonempty answer list for rubric-only activities. The provider schema also admits a rubric missing R04's required evidence dimension. A candidate can therefore obey the provider schema and fail the editor contract. G03 and R08 already have narrower authoring representations; the other 17 activity IDs still pass through the shared standard schema. The current stage keeps a single repair flag and transient feedback. Technical failure clears automation. Continue restores validated artifacts but does not carry forward the failed attempt's strategy. The observed behavior follows the current policy.

## User-visible contract

A learner asks once. The server schedules the lesson from the first accepted submission, or from one initial whole-lesson confirmation where spending policy requires one. While work is queued, generating, automatically repairing, or waiting for capacity, the chat displays the current part and exercise, preserves previews, and offers Stop. Closing the tab or reconnecting has no effect on execution. Once all required units validate, the learner receives one ordered proposal. Insert and Save retain their existing explicit semantics.

Checkpoints, worker handoffs and recoverable format errors need no learner action. Genuine funding or source decisions, a changed plan, policy refusal, or an ambiguous upstream dispatch with no reconciliation path require specific recovery UI. A repeat of the same exhausted strategy must not present another identical Continue. Preserve the original plan, completed previews and a clear explanation of what remains if the service cannot finish within its authority.

## Implementation sequence

1. **Correct the generation contract.** Start with the actual R04 provider declaration. Ask for the question, exemplar answer and rubric requirements keyed by the required dimensions, including passage evidence. Compile known metadata, source handles and rubric structure in the host. The provider cannot specify a prepared answer list for R04. Keep the canonical validator, editor, grading and source checks intact. Remove editor-shaped examples that conflict with the new declaration. Verify the serialized schema and an actual pinned-SDK call. When continuing this existing revision, reuse its saved reading, R01 and R08.

2. **Bring the whole catalog under the same rule.** Define a catalog-driven authoring contract per interaction and checking family. Let activity definitions declare their particular inputs and semantic requirements. The worker already knows the selected activity, languages, source choices and expected unit count. Use those to build a one-unit response shape. Ask for educational content once. Choose from host-authorized source handles where choices are needed; allocate persistent IDs, references, keys and fixed metadata on the server. Retain special semantics such as classification and evidence rubrics. Validate the compiled result against the canonical contract and the frozen source. Add a coverage check that fails when a new catalog entry lacks a compiler or contract test. Audit all 19 activities plus mixed calls and revision consumers before removing any shared path.

3. **Persist attempt history and choose a different recovery action.** Key attempts by run, revision, task, unit ordinal and dependency fingerprint. Record attempt identity, authoring schema/strategy version, dispatch and settlement evidence, safe invariant code/path, retry count and next eligible time. Avoid retaining rejected text or source content in diagnostics. The worker records the failed attempt before scheduling recovery. An infrastructure restart or new browser request must not reset this history. Start with a bounded policy: one initial candidate, one targeted repair for a measured invalid response, and at most one independently budgeted fallback that materially changes the generation strategy. A fallback might ask only for missing rubric evidence and reuse the already validated fields from a safely retained, private intermediate candidate, or regenerate from a simpler content-only representation. Use full regeneration if field preservation would mix inconsistent answers or require new private persistence. Verify the fallback independently and revalidate the entire exercise. Suppress further attempts with the same exhausted strategy and failure signature. Never fabricate answers, change a specified exercise type, or silently omit an exercise.

4. **Authorize a whole lesson and advance its ready units.** Keep the existing durable plan, worker, source hashes, checkpoints, idempotency and settlement as the foundation. Quote or admit one finite lesson envelope up front: customer credits, provider expense including unsuccessful calls, time, attempts and stages. Reserve sufficient headroom for allowed retries and route changes only as current policy permits. If the requested job cannot reasonably fit, surface that once before lengthy generation. Per-stage limits, leases, capacity locks and provider-call deadlines still apply. Under the same remaining authority, the server may advance after a *settled, recoverable* rejection and may allow an independent ready task such as grammar to proceed while the reading exercise is waiting. Dependent exercises must use the actual saved predecessor. Final assembly uses plan order and requires every requested unit. No concurrency increase is needed for the first release. Temporary pre-dispatch capacity or a conclusive transient rejection may wait with bounded backoff under the remaining authorization. Unknown provider outcomes need reconciliation or informed consent, never blind replay. Stop must fence in-flight and queued recovery and suppress subsequent dispatch. Define quote expiry separately from the execution lifetime of an accepted plan. Keep existing cost caps until a revised authorization rule is accepted.

5. **Protect existing runs.** Reconstruct progress from validated checkpoints and preserve artifact IDs. Use historical receipts when they unambiguously identify an attempt. Where old rows do not retain failure details, record only what can be proven. Retain the saved run's pause and revoked authority. A deliberate resume on the revised contract can authorize the remaining work once; it must not regenerate the plan or restart saved units. A rollout must not silently enqueue old paid jobs.

6. **Prove the learner journey.** Reproduce the R04 contradiction with both a provider-schema-accepted nonempty answer list and a rubric lacking required evidence. Test all 19 provider schemas, compilers and semantic checks with valid and near-valid examples and actual SDK serialization. Replay the French plan from one submitted message and at most one initial consent. Inject a recoverable rejection at exercise 3, a stage handoff, an idle reconnect and a worker restart. Assert zero intermediate manual Continue requests, preserved checkpoint identities, three distinct comprehension exercises, five grammar exercises, correct dependencies and ordering, one final proposal, bounded provider calls and exactly-once accounting. Repeat from a saved two-exercise prefix. Also prove wake-up after capacity returns, repeated identical errors stop within the cap, a refused/uncertain dispatch does not replay, and cancellation prevents queued work. Use disposable PostgreSQL and Redis for scheduler races. Verify a separately authorized live synthetic lesson through the production route before claiming live reliability. Measure completion without intervention, validation failures by activity/schema version, retry recovery, and cost/time per completed lesson.

## Agent choice

Use the existing planner and a constrained author for each ready unit. The durable scheduler owns progress, retries, deadlines and spending. An exercise-family specialist can be one bounded fallback if evaluation shows it improves outcomes. Giving autonomous agents the same contradictory schema or independent retry budgets would preserve this incident and multiply costs. Introduce parallel specialists only after the sequential one-submit journey meets its acceptance criteria.

### Offline reproduction

Two synthetic candidates were run through the actual R04 authoring schema and host assembly. Both passed authoring validation. The first failed canonical validation at acceptedAnswers; the second omitted the evidence dimension and failed at semantics.checking.rubric. This reproduces the schema defect independently of the provider. Only the first path is confirmed on the latest saved turn.
