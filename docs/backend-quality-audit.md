# Backend engineering and agent workflow audit

**Decision.** Prioritize session revocation, dependencies at untrusted-input boundaries, and transcription settlement. Each has a concrete failure mode with consequences for users or operators. The backend already has good building blocks for the repairs, including fenced operations, typed contracts, disposable database tests and module-level policies. A backend-wide rewrite would spread the verification effort across code that this audit found no reason to change.

**Snapshot.** Reviewed on 2026-11-25 at `e940e51d7c392abdab34d3c249f65563450fec8a` on local `main`. The working tree initially contained unrelated web/Storybook work. During review, main advanced to `641c2570` with that work. A scoped diff confirmed identical backend, skill, agent, package, lint and cited web-consumer sources across the two revisions. The deliverable is a current-state audit of backend source and the workflow used to write it. The findings describe the audited revision. The [implementation record](../.agent/improvements/backend-quality-audit-followup.md) tracks subsequent fixes, verification and outstanding work. “High” means prioritize remediation or exposure assessment. “Medium” means a concrete correctness, operational or maintenance issue with a bounded trigger. Workflow priorities describe leverage for future changes.

## Security and integrity

### S1 · High · Sign-out-everywhere can race a refresh

The authentication service promises to revoke the user’s sessions. Session issuance takes the user lock. Refresh rotation takes the predecessor session lock, later locks the user, and inserts a successor. Bulk revocation opens a transaction and updates matching sessions without first locking the user. Under PostgreSQL Read Committed, the update can begin before the successor is visible and finish after rotation commits. A successor may remain usable after a successful sign-out-everywhere. Password change introduces another consequence of the same design. It locks the user first and then updates sessions, so it can deadlock with rotation. This is a source-based concurrency finding, conditional on isolation and scheduling. No production incident or concurrent DB execution was observed. [Session service](../apps/backend/src/modules/authentication/application/authentication-service.ts#L886) · [Issuance, password change, revocation and rotation](../apps/backend/src/modules/authentication/infrastructure/persistence/drizzle/auth-session-operations.ts#L131) · [Bulk update](../apps/backend/src/modules/authentication/infrastructure/persistence/drizzle/auth-persistence-support.ts#L159)

Use one per-user serialization point across issue, refresh, password change and revocation. When starting with a digest, resolve the owner, acquire the user lock, then reread and validate the session under its lock. Preserve replay-family revocation and distinguish a legitimately new login after logout. Close with two-connection disposable PostgreSQL tests for overlapping rotation and all-session revocation, and rotation and password replacement. Assert the resulting usable sessions and absence of a deadlock. Existing tests exercise simultaneous rotations and sequential stale-token logout. [Repository concurrency tests](../apps/backend/tests/integration/modules/authentication/infrastructure/drizzle-authentication-repository.test.ts#L817)

### S3 · Medium · Authentication audit failure and expiry lack operational evidence

After committing authentication work, the service catches recorder errors and delegates alerting. Its production recorder only inserts a row. A failed insert can therefore lose incident evidence silently while authentication continues. Separately, security events have an indexed 180-day expiry timestamp. The repository search located redaction on account purge and pruning for admin/MCP audit, but no executor for expiring these authentication events. An external retention job could fulfill that responsibility. [Service catch](../apps/backend/src/modules/authentication/application/authentication-service.ts#L1550) · [Production recorder](../apps/backend/src/modules/authentication/infrastructure/persistence/drizzle/drizzle-security-event-recorder.ts#L17) · [Expiry schema](../apps/backend/src/modules/authentication/infrastructure/persistence/drizzle/schema.ts#L339) · [Admin pruning scope](../apps/backend/src/modules/administration/infrastructure/persistence/drizzle/drizzle-administration-operator.ts#L244)

Emit a rate-limited, payload-free failure counter while preserving the committed auth outcome. Identify the deployed retention owner. If none exists, add indexed, bounded expiry batches and monitor the age of the oldest overdue row. Verify recorder rejection, fresh and expired records, and repeated cleanup runs. Keep user IDs, tokens and event contents out of metrics.

### L7 · Medium · A valid multilingual search can generate an invalid next page

The manual flashcard picker stores the whole search in base64url-encoded JSON. The shared contract accepts a 200-code-point search but limits cursor length to 512 characters. With ordinary UUIDs and a 120-character Japanese search, the same serialization produced **676 characters**. The installed schemas accepted the initial query and rejected the resulting cursor in both the response and follow-up request. A learner can lose access to the next page of matching cards. Use a fixed-length fingerprint of the normalized search, keep dictionary and version binding, and round-trip the emitted cursor through both actual schemas. Extend the existing repository continuation test with enough matching entries, Unicode at the maximum and strings requiring JSON escaping. ## Performance and capacity

**P1 · Medium · A workbook list at its cap issues 1,002 SQL statements.** One statement locks the owner row, one selects workbooks, then two per workbook fetch ordered note summaries and share existence. The total is `2 + 2W`, excluding transaction control and HTTP authentication. `Promise.all` schedules these calls inside the same transaction. The owner lock remains held through result assembly, so a read can delay an edit by the same owner. Batch members for all selected IDs and fetch share presence in bulk. Preserve ordering, owner filters, empty lists and isolation. Compare response equality and statement counts at 1, 100 and 500 workbooks, then measure lock wait with a concurrent edit. [List and hydration](../apps/backend/src/modules/knowledge/infrastructure/persistence/drizzle/workbook-store.ts#L66) · [Owner row lock](../apps/backend/src/modules/knowledge/infrastructure/persistence/drizzle/knowledge-transaction.ts#L46) · [Existing bulk projection pattern](../apps/backend/src/modules/knowledge/infrastructure/persistence/drizzle/learner-workbook-progress.ts#L64)

**P2 · Medium · Transcription lease renewal transfers audio that the heartbeat discards.** Initial dispatch needs the bytes. The default 15-second heartbeat rereads the fenced audio under capacity and owner locks to confirm eligibility. For an asset of size B and H successful renewals, this path transfers H × B additional payload bytes before wire encoding. Four renewals of a 5 MiB file add 20 MiB. Keep token, fence, ownership, deadline, cancellation and source-integrity predicates. Move renewal eligibility into a metadata-only SQL check under the same authority and keep bytes on the dispatch path. Measure transferred bytes and lock duration, and prove invalidated sources and stale workers still fail closed. [Timer](../apps/backend/src/modules/knowledge/application/transcription-worker.ts#L51) · [Heartbeat transaction](../apps/backend/src/modules/knowledge/infrastructure/persistence/drizzle/transcription-execution.ts#L148) · [Audio query](../apps/backend/src/modules/knowledge/infrastructure/persistence/drizzle/transcription-worker-source.sql)

**P3 · Medium · Report refresh capacity conflicts with the freshness window.** One default API instance waits 15 seconds after completing each single-range refresh. Reads reject snapshots older than 60 seconds and allow up to 64 registered ranges. With eight continually active ranges, a full cycle takes at least 120 seconds before query time. A previously prepared range can repeatedly revert to “being prepared”. Use the worker’s existing “did work” result to drain a bounded batch within a time budget, or validate unchanged versions cheaply while honoring the freshness contract. Retain leases and pool limits. Exercise multiple ranges with a fake clock, followed by concurrent DB registration, refresh and invalidation. [Scheduler](../apps/backend/src/modules/ai-credits/infrastructure/accounting-report-worker.ts#L11) · [Registration, freshness and claim](../apps/backend/src/modules/ai-credits/infrastructure/persistence/drizzle/accounting-report-operations.ts#L44) · [Production wiring](../apps/backend/src/index.ts#L703)

**P4 · Medium · Temporarily blocked jobs can hide eligible work from the Texts worker.** The claim reads the oldest 25 due, supported jobs, then rejects candidates whose provider circuit or actor/provider capacity is unavailable. A blocked prefix can stop the claim from reaching the next healthy route. This delays other learners while the prefix remains blocked. Apply eligibility before the cutoff or give temporarily blocked jobs a bounded deferral. Preserve fairness, fencing and capacity accounting. Verify an eligible job immediately behind a blocked prefix completes, and that deferred jobs resume when their route recovers. [Candidate selection and checks](../apps/backend/src/modules/texts/infrastructure/persistence/drizzle/texts-job-claim.ts#L136) · [Admission limits](../apps/backend/src/modules/texts/infrastructure/persistence/drizzle/texts-job-admission.ts#L219)

**Profiling candidate · Accounting materialization reads historical detail.** A short report interval can still load provider history before the end date, filter it repeatedly by provider in Node, and execute aggregates per included bill. Snapshot materialization, dedicated connections and bounded registration already protect the request path. Before changing reconciliation SQL, measure rows transferred, heap, buffers and query time on multi-year synthetic data. Compare database grouping and latest-balance-as-of queries within the existing snapshot. Check period boundaries, unknown expenses and historical balances for exact equality. [Materializer](../apps/backend/src/modules/ai-credits/infrastructure/persistence/drizzle/accounting-report-operations.ts#L218)

All workload figures above are derived from statements, payloads or scheduling rules. Production latency, queue wait, CPU and memory were not measured.
